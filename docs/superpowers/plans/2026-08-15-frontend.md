## Context

后端 sidecar 是一个完整可信的底座（安全闸门/鉴权/行数上限/连接池/知识库 v2/审计，全部有测试）。**从"可信后端"到"可用产品"之间的最大缺口是真实前端**。本计划搭建 Electron + React 前端，对接现有 API，实现设计原型定义的交互（数据主场 + AI 副驾 + 安全三色）。

## 技术栈（已定）

Electron + React 18 + TypeScript + Vite + Zustand。脚手架用 **electron-vite**（main/preload/renderer 一体化构建）。E2E 用 Playwright（团队在 quance 用过），单测用 vitest。

## API 契约要点（前端对接依据）

- **鉴权**：除 `GET /health` 和 OPTIONS 外，所有请求带 `X-Cleared-Token` 头。token 由 sidecar 启动时写入 `data_dir/sidecar.token`（默认 `~/.cleared/`），或 env `CLEARED_SIDECAR_TOKEN`。
- **连接**：`GET/POST /api/v1/connections`、`GET/PUT/DELETE /{id}`、`POST /{id}/test`。响应是 `public()` 打码后的配置（password="•••"）。
- **Schema**：`GET /connections/{id}/schema?refresh=` → `{tables:[{name,kind,comment,column_count}], columns:[{table,name,type,nullable,pk,fk,default,comment}], foreign_keys:[{table,column,ref_table,ref_column}]}`；`/{table}`、`/{table}/preview?limit=`、`/{table}/ddl`。
- **查询**：`POST /api/v1/query {connection_id, sql, origin:"manual"|"ai", confirm, limit, offset}` → 四态：`allow`(columns/types/rows/truncated/elapsed_ms) / `review`(preview_rows+needs_confirm) / `block`(reason+suggestions) / `executed`(affected_rows)。`POST /query/cancel`。`POST /sql/format`。
- **AI 聊天**：`POST /api/v1/ai/chat {connection_id, messages[], provider?, base_url?, api_key?, model?, include_data, table?}` → **SSE 流**，事件：`turn_start` → `think{text}` → `text{content}` → `sql_card{card:{tier,verdict,sql,sub,reason?,preview_rows?}}` → `done` / `error{message}`，末尾 `data: [DONE]`。**服务端无状态，前端每次带全量消息历史**。
- **编辑器选中**：`POST /api/v1/ai/selection {connection_id, sql, kind:"explain"|"optimize"|"risk"}` → `{kind, text}`。
- **审计**：`GET /api/v1/audit?connection=&verdict=&limit=` → `{count, entries}`。
- **设置**：`GET/PUT /api/v1/settings` → `{ai_provider, ai_base_url, ai_api_key(masked), ai_model, ai_temperature, ai_timeout, gate_review_threshold}`。
- **知识库**：`POST /knowledge/{id}/build`、`GET /knowledge/{id}/retrieve?q=&table=&k=`、`GET /docs`、`PUT /docs`(标注)。

## 关键设计决策

### 1. 执行一律走 POST /query —— SSE 卡片是"提案"，不是"执行"
AI 的 `run_query`/`run_dml` 工具在服务端只做评估（读给行数、写给预览），**不回传行数据**。所以：
- **读卡片**：点"运行" → 前端 `POST /query origin=manual` → allow → 行数据进结果区（复用现有 API，无需改后端）
- **写卡片**：卡片已带 `preview_rows` → "确认" → `POST /query confirm=true` → executed
- **DDL 卡片**：发送到编辑器，不执行
这条模式让安全闸门保持唯一执行路径，且不用改后端流。

### 2. 后端小改动（可选但推荐）：`POST /query` allow 响应加 `tables`
闸门 Assessment 已算出 `tables`，响应里带上即可（约 2 行 + 1 测试）。用途：结果区刷新后，图谱视图高亮"本次查询触碰的表"，还原原型里的图谱行为。不做也能用——图谱先高亮选中表 + FK 邻居。

### 3. sidecar 生命周期由 Electron 主进程管理
- 启动时 spawn `python -m uvicorn app.main:app --port 8765`（cwd 指向 backend，用项目 venv）；env `CLEARED_SIDECAR_CMD` 可覆盖（外部已起时设 `CLEARED_EXTERNAL_SIDECAR=1` 不 spawn）
- 轮询 `GET /health` 直到就绪 → 读 `sidecar.token` → 通过 preload `contextBridge` 暴露 `{baseUrl, token}` 给渲染进程
- 退出时若为自己 spawn 的子进程则 kill
- 首次运行若无连接：创建 SQLite 演示连接指向 seed 生成的 `~/.cleared/demo.db`

### 4. 首屏体验
无连接时显示空态 → "使用演示库"一键创建 SQLite demo 连接。让新用户 10 秒内跑到"问数据库"。

## 风险与取舍

- **渲染进程网络模型**：fetch 直接打 localhost 即可（CORS 已放开），不需要走 IPC 代理；token 从 preload 拿一次。
- **打包 sidecar**：electron-builder 无法直接带 Python 环境 → P2 用 PyInstaller 把 sidecar 打成单二进制，MVP 先要求 dev 环境。
- **图谱的"命中表高亮"**依赖后端 `tables` 小改动；不加也能先跑（选中表+邻居）。
- **include_data**：默认关；聊天里提供"AI 查看结果明细"开关，开时流内由工具按需带行（隐私红线不变）。
