# 前端国际化（i18n）设计方案

> 范围：仅前端 · 语言：zh-CN（默认）/ en-US · 机制：轻量自研 · 词典打包进前端 bundle
> 日期：2026-08-20

## 1. 目标与范围

- 为整个前端 SPA 接入中/英双语，支持「设置」内一键切换。
- 语言：`zh-CN`（默认）、`en-US`。
- 范围：**仅前端**。后端代码、日志、注释、AI 提示词一律不动。
- 所有用户可见的**静态 UI 文案**都必须国际化为 `t(key)`；**品牌词除外**（如产品名 `tabletalk`）。
- 约定：**后续新增功能的用户可见文案也必须走 `t()`**，并同步写入两个词典（见 §7 强制兜底）。这是长期纪律，不是一次性迁移。

## 2. 非目标（明确不做）

- 后端用户可见文案本地化（把错误/提示改成返回 code、由前端按 code 翻译）——本期不做。
- 后端日志、注释、AI 提示词翻译——不做。AI 提示词多语言会直接改变 AI 行为，风险高；日志/注释翻译无用户收益。
- 服务端动态返回的错误文本（如 API `e.message`）本期仍按服务端原语言展示——属「数据/服务端文案」，不在静态 UI 抽取范围内。

## 3. 架构

- 新增 zustand store `useI18n`：`{ locale: 'zh-CN' | 'en-US', setLocale, t }`。
- `t(key: string, vars?: Record<string, string | number>): string`
  - 从当前 locale 词典取值；
  - 缺失时回退 `zh-CN`；
  - 仍缺失则返回 `key`（开发期可一眼看出漏翻）。
- **响应式**：组件用 `const { t } = useI18n()` 取到的 `t` 绑定当前 `locale`；`locale` 变化时所有用到 `t` 的组件自动重渲染（一次性重渲染，无持续开销）。
- 词典作为静态 TS 模块在**构建时 import**（打包进前端 bundle，**不运行时 fetch 后端**）。理由：范围限定前端-only、后端不动；零网络往返、切换瞬时、无 loading 态。

## 4. 词典

- 文件：`src/renderer/src/locales/zh-CN.ts`、`src/renderer/src/locales/en-US.ts`。
- 两个平行对象（默认导出 `const dict = { ... }` 或命名导出），结构一致。
- **语义点号 key**，按页面/功能分组，例如：
  - `nav.workspace` / `nav.knowledge` / `nav.securityAudit`
  - `gate.tier.read` / `gate.tier.write` / `gate.tier.ddl`
  - `audit.blocked` / `audit.review` / `audit.export` / `audit.totalCount`（插值）
  - `settings.language` / `settings.title`
  - `common.confirm` / `common.cancel` / `common.loading`
- 插值示例：`t('audit.totalCount', { n: total })` → 中文 `共 {n} 条` / 英文 `Total {n}`。
- 品牌词（如 `tabletalk`）在 key 值中原样保留，不翻译。

## 5. 切换开关

- 位置：`SettingsDrawer`（设置抽屉）内新增「语言 / Language」**分段控件**：`中文 | English`。
- 行为：点选即 `setLocale(...)`，并写入 `localStorage`（key `tabletalk-locale`），默认 `zh-CN`；刷新后保持。
- 整页即时切换，无需刷新、无 loading。

## 6. 抽取实施（重头戏）

- 对 32 个含中文的前端源文件，将硬编码中文逐一替换为 `t('...')`。
- 按页面/区域分批（如：基础设施 → 各页面 → 组件 → store → API 文案 → hooks/utils），每批跑 `npm run typecheck` 保底。
- 产品名等品牌词跳过（不抽）。
- 文件清单见附录 A。

## 7. 后续功能的强制约定（兜底）

- 任何新增/修改的用户可见文案 **必须** 通过 `t()`，禁止再次出现硬编码中/英混排字符串。
- 新增 key 必须**同时**写入 `zh-CN.ts` 与 `en-US.ts`。
- **key 对齐测试**（见 §8）保证两词典 key 集合完全一致，漏写任一语言即失败，从机制上防止回归。

## 8. 验证

- **词典 key 对齐检查**（新增，**零依赖 node 脚本** `frontend/scripts/i18n-parity.mjs`）：用 `import` 加载两个词典，断言 key 集合相等且所有 value 非空/非占位；不通过则 `process.exit(1)`。前端无测试运行器（无 vitest/jest），故用 node 脚本而非单测框架。可在 `package.json` 加 `"i18n:check": "node scripts/i18n-parity.mjs"`，并视情况接 CI。
- 前端 `npm run typecheck` 必须通过（每批抽取后）。
- 前端 `npm run build` 必须通过。
- 后端测试不受影响（后端未改动）。
- 手动验收：设置内切到 English，逐页检查无残留中文（品牌词除外）；切回中文正常。

## 9. 性能

- 词典打包进 bundle，原始文案约数十 KB，gzip 后增量约 20–40KB，对现有包体影响可忽略。
- `t()` 为 O(1) 查表；切换语言为一次性重渲染。无持续卡顿风险。
- 不采用按需动态 `import`（过早优化，当前体量不需要）。
