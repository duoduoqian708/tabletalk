# 意图-技能-工具 定义 v1（归档）

> 来源：2026-08-22 与 AI 对话逐条归档。状态：已共识，待逐项打磨实现。后续改每把 tool/skill 的具体实现以此为基线。

## 1. 设计总则
- 话术统一：**场景 = 技能（skill）**，符合 Agent/skill 定义
- 2 层直连：意图 → 技能（场景）→ 工具；技能即场景的别名+工具白名单+指导语，不做硬编排
- 工具原子化：一把一件事，无业务分支
- 门禁两层：硬拦归本地规则（不暴露为 tool），语义审核归大模型（单独一把 `审核圈` tool，只出意见不给放行权）
- 审计写不暴露：审计只查不写，写由后端隐式落盘

## 2. 意图（6 个）
| 意图 | 说明 | 备注 |
|---|---|---|
| 查 | 查数据 + 看表结构，合一。不猜边界，工具内分流 | 原 query + schema 合并 |
| 出报告 | 要一份带图表的分析，唯一多轮编排 | 需澄清→计划→多查→汇总 |
| 改数据 | 改/删/增数据 | 高危，需审核+确认 |
| 改结构 | 加列/建表/建索引等改表结构 | 只出草案，不执行 |
| 查审计 | 查审计日志/被拦原因 | 只查 |
| 闲聊 | 与库无关 | 拒答引导 |

> 管知识（“图上加条线/改知识”）暂不单列意图，归到查/改的后续动作，后续若量大再单列 `管知识` 意图。

## 3. 工具（10 把原子）
| # | 工具 | 干嘛 | 输入 | 输出 | 信任 | 是否需确认 |
|---|---|---|---|---|---|---|
| 1 | 看结构 | 看库有哪些表/某表有哪些列 | 表名可选 | 表结构 | 只读 | 否 |
| 2 | 向量读 | 按语义找相似表/知识 | 问题文本 | 候选表/知识片段 | 只读 | 否 |
| 3 | 向量写 | 新增/更新知识片段 | 知识文本、标签 | 写入结果 | 可变 | 轻确认 |
| 4 | 图读 | 查表之间的关联 | 表名 | 关联表列表 | 只读 | 否 |
| 5 | 图写 | 加/删图上的一条线 | 起点表、终点表、关系 | 更新结果 | 可变 | 轻确认 |
| 6 | 数据库读 | 跑一句只读查询 | SQL | 结果卡 | 只读 | 否 |
| 7 | 数据库写 | 跑一句改数据语句 | SQL | 预览行数+影响面+回滚 | 可变 | 需确认 |
| 8 | 结构写 | 生成改表脚本 | SQL | 草案 | 只读 | 否（手点执行） |
| 9 | 审计查 | 查审计日志 | 时间范围、判定、连接等过滤 | 审计条目 | 只读 | 否 |
| 10 | 审核圈 | 审“圈画得准不准” | 原话、圈条件、影响行数、上下文 | 是否贴合+建议 | 只读 | 否 |

> 说明：向量读/图读在查的检索阶段自动串（向量召回+图扩展），也可单独调；数据库写前必调审核圈；审计写不暴露。

## 4. 技能 = 场景（1 技能对 N 工具）
| 场景 | 归属意图 | 可用工具 | 说明 |
|---|---|---|---|
| 看结构 | 查 | 看结构、向量读、图读 | 跳检索快路径 |
| 查数据 | 查 | 看结构、向量读、图读、数据库读 | 常规查 |
| 出报告 | 出报告 | 问清楚、看结构、向量读、图读、数据库读 | 澄清→计划→多查→汇总 |
| 改数据 | 改数据 | 看结构、审核圈、数据库写 | 审核后预览确认 |
| 改结构 | 改结构 | 看结构、结构写 | 只出草案 |
| 查审计 | 查审计 | 审计查 |  |
| 拒答 | 闲聊 | 无 | 固定文案 |
| 改图 | 管知识 | 图写 | “加条线”场景 |
| 改知识 | 管知识 | 向量写 | “改描述/标签”场景 |

## 5. 意图 → 技能（场景）→ 工具 矩阵
- 查 → [看结构, 查数据] → [看结构/向量读/图读/数据库读] + 问清楚（缺参时）
- 出报告 → [出报告] → [问清楚/看结构/向量读/图读/数据库读×N]
- 改数据 → [改数据] → [看结构→审核圈→数据库写]
- 改结构 → [改结构] → [看结构→结构写]
- 查审计 → [查审计] → [审计查]
- 闲聊 → [拒答] → []
- 管知识 → [改图/改知识] → [图写/向量写]

## 6. 前端展示约定
- 总进度 = 意图分类结果
- 子任务 = 后端实际调了哪把工具就展哪把，动态加载
- 每步前后端流式：`subtask_start` / `think` / `text` / `subtask_done` 逐条推
