# 01 · 定位与原则

## 1. 产品定位

**一句话**：让人人敢查数据库，让企业敢让 AI 进数据库。

**电梯陈述**：TableTalk 是自托管的 AI 数据库查询工具。自然语言进来，SQL 出去；AI 可以写，但本地安全闸门保证它永远写不危险。行数据不出内网，发给模型的只有脱敏后的结构和聚合，每一笔都列在清单里、记在审计里。个人开源免费，团队按"可信网关"付费。

**形态**：本地 FastAPI sidecar + 浏览器 Web SPA（同源托管）。sidecar 持有全部数据库连接、安全闸门与 AI 编排--这个架构是刻意的，它将演进为团队网关（见 05）。

## 2. 三根支柱

| 支柱 | 优先级 | 服务对象 | 内涵 | 对立面 |
|------|--------|----------|------|--------|
| **可信** | 主线 | 企业 / DBA | AI 能写 SQL 但永远写不危险；每步可解释、可审计 | 黑箱 AI、静默执行 |
| **方便** | 副线 | 不写 SQL 的业务人员 | 敢问（物理上点不坏）、会问（脚手架）、信答案（可追溯） | 吓人的专业工具界面 |
| **安全** | 基础 | 合规 / 平台团队 | 受控出网：行数据不出，出网内容可枚举、已脱敏、全留痕 | "零出网"的不现实承诺 |

三者的关系：**可信让企业敢部署，方便让业务被允许碰到数据，安全让前两者在外网大模型时代依然成立。** 可信与方便是一枚硬币：很多公司不是业务不想查数，是 IT 不敢给权限。

## 3. 目标用户与买家

**买家和用户是两个人，产品要有两个第一屏：**

- **买家（决策者）**：DBA / 平台团队 / CTO。他们的第一屏是**控制台**：策略配置、审计报表、出网清单、成员与权限。
- **用户（日常使用）**：业务人员、运营、分析师、开发者。他们的第一屏是**提问框**：猜你想问、星图、对话。

用户分层与阶段：

| 阶段 | 用户 | 商业模式 |
|------|------|----------|
| 第一期（开源） | 个人开发者、小团队试用 | 免费，攒口碑与社区 |
| 第二期（安全落地） | 有合规要求的团队 | 仍免费，验证能否过安全评审 |
| 第三期（团队网关） | 中大型企业 | 凭证保险库 / 审批流 / 集中管控 / 合规报表收费 |

## 4. 竞争坐标

- **vs DBeaver / DataGrip / Navicat**：他们是"给会 SQL 的人的工具"。我们不拼表格编辑器功能，卖的是"让不会 SQL 的人进得来、且管得住的门"。
- **vs Text2SQL 创业公司**：他们卖聪明（准确率），我们卖放心（本地、模型无关、可审计）。准确率会被模型进步拉平，信任故事不会。
- **vs BI（Metabase / Superset）**：明确不进入仪表盘赛道（见反目标）。报告模式止步于"AI 写有数字依据的叙述"。

## 5. 统一叙事：本地可信层（TrustCore）

闸门、脱敏、出网清单、审计，是同一件事的四个面：**不依赖任何模型的本地防线**。产品内（设置页、文档、营销页）统一用"本地可信层"呈现，不作为四个孤立功能罗列。

可验证性是护城河：规则本地可读、离线依然拦截、攻击测试集公开可跑。安全故事最怕"你说是就是"，必须做成"你可以自己来试"。

## 6. 六条设计原则（一切功能决策的尺子）

1. **先问再动**：每个新功能先问--它让信任更可信了吗？让查询更无惧了吗？两者皆无则不做。
2. **本地规则优先于模型判断**：凡"守门"类决策（闸门 / 脱敏 / 路由）必须离线可跑、规则可读、结果可审计。**模型只负责"写"，永远不负责"放行"。**
3. **行数据默认不出网**：结构可以出去，出去的要留痕；明文数据必须逐查询提权。
4. **透明优于纯洁**：宁可展示真实限制（"这条查询需要明文数据，请提权"），不承诺做不到的纯洁。
5. **给 DBA 控制台，给业务提问框**：两个第一屏，不要一个界面塞两种人。
6. **确定性优先**：mock 默认、离线可演示、测试全绿。工程上的纪律就是商业上的弹药（销售场景 30 秒离线演示完整体验，不连库、不要 key）。

### 专节：为什么星图不做 2D/3D 切换（决策记录）

- 3D 关掉相机不会变成好 2D：用户要 2D 时想要的是"可读"（标签不重叠、能顺着边读 FK、能扫一眼找到表），这靠力导向布局，不靠拍扁相机。扁掉的星图继承 3D 全部毛病、失去 3D 美感，两头不占。
- 双倍维护成本：交互、命中检测、e2e、无障碍全要两套。旧版 SVG 力导向图谱（GraphCanvas）当初就是被 3D 星图替换的。
- **替代方案**：把 2D 的主要诉求（找得到、看得清）在 3D 里满足--搜索定位、显式旋转控制、选中后邻居局部散开（见 02-D 系列）。若未来出现持续的真实信号（开源 issue 区反复出现"要平面图"），再做一个**目的不同的 2D 视图**（表关系图模式，服务读拓扑、规划 join），与星图并列两扇门，而非同一个房间的灯开关。
- 在此之前，触发重评的信号：issue 区 ≥10 个独立用户提出平面视图需求；或单库表数 >80 时球面布局可读性崩坏。

## 8. 北极星指标（防跑偏的锚）

| 支柱 | 指标 | 定义 | 目标 |
|------|------|------|------|
| 可信 | 拦截可解释率 | BLOCK/REVIEW 事件中附有具体规则与原因的比例 | 100% |
| 可信 | 成本拦截率 | 高成本查询执行前被 REVIEW 的比例 | 可配置、有基线 |
| 方便 | 零编辑采纳率 | AI 答案未经修改 SQL 直接采纳的比例 | 核心健康度 |
| 方便 | 首答时长 | 新用户从建连接到第一个满意答案的时间 | 分钟级 |
| 安全 | 出网可枚举率 | 有清单与审计记录的模型调用比例 | 100% |
| 复利 | 问题库命中率 | 经保存问题库直接命中的查询比例 | 持续上升 |

全部来自日志体系（埋点字段见 06）。指标的意义不是 KPI 而是方向盘：功能取舍摇摆时看这几个数。
