# TableTalk 产品设计方向（Product Direction）

> 日期：2026-08-20 · 状态：方向性文档（非实现方案）
> 前提：后端与前端 M2–M4 已完成并验证（连接/图谱/结果表、AI 对话轨、报告模式、审计页、知识库 v4、三档安全闸门）。本文回答"接下来往哪走、为什么、按什么顺序"。

---

## 1. 定位与主张

### 一句话定位

**让人人敢查数据库，让企业敢让 AI 进数据库。**

### 三根支柱（按优先级）

| 支柱 | 优先级 | 服务对象 | 一句话内涵 |
|------|--------|----------|-----------|
| **可信** | 主线 | 企业 / DBA | AI 能写 SQL，但永远写不危险；且每一步可解释、可审计 |
| **方便** | 副线 | 业务人员 / 不写 SQL 的人 | 不懂 SQL 也不畏惧查数：敢问、会问、信答案 |
| **安全** | 基础 | 合规 / 平台团队 | 行数据不出内网；出网内容可枚举、已脱敏、全留痕 |

三者的关系：**可信让企业敢部署，方便让业务被允许碰到数据，安全让前两者在外网大模型时代依然成立。** 可信与方便是一枚硬币的两面——很多公司不是业务不想查数，是 IT 不敢给权限；我们卖的就是那把钥匙。

### 对外的安全主张（放弃"零出网"，改卖"受控出网"）

> **你的行数据永远留在内网；发给模型的只有脱敏后的结构和聚合，而且每一笔都列在清单里、记在审计里。**

不承诺做不到的事，但把"必须用外网大模型"这个现实包进一个有 UI、有策略、有日志的产品面里。

### 竞争坐标

- **vs DBeaver / DataGrip / Navicat**：他们是"给会 SQL 的人的工具"，我们是"让不会 SQL 的人也进得来、且管得住的门"。不拼表格编辑器功能。
- **vs Text2SQL 创业公司**：他们卖聪明（准确率），我们卖放心（本地、模型无关、可审计）。准确率会被模型进步拉平，信任故事不会。
- **vs BI（Metabase 等）**：明确不进入仪表盘赛道（见 §6 反目标）。报告模式止步于"AI 写有数字依据的叙述"。

### 核心叙事：本地可信层（TrustCore）

闸门、脱敏、出网清单、审计，本质是同一件事的四个面：**不依赖任何模型的本地防线**。产品叙事里统一命名、统一呈现——四个功能变成一面盾牌。这个主张的可验证性是护城河：规则本地可读、离线依然拦截、攻击测试集公开可跑。

## 2. 支柱一：可信（把引擎盖下的东西推到台前）

现状：闸门是机制，用户感知到的是弹窗。目标：让信任**可演示、可解释、可配置**。

### 2.1 爆炸半径（Blast Radius）

DML 确认前，不只显示"影响 238 行"，利用知识图谱展示波及面：

- 卡片：受影响表、FK 级联路径（orders → order_items → payments）、约束提示、预估行数。
- 星图联动：确认时在 3D 星图上点亮受波及子图（琥珀色高亮 + 红色边），用户不是在"读风险"而是在"看见风险"。

### 2.2 回滚剧本（Rollback Script）

确认执行 DML 前，自动生成对应的备份 / 回滚 SQL 附在确认框里。叙事闭环：AI 帮你写，闸门帮你兜底，出事还能退回来。

### 2.3 拦截可解释

每次 BLOCK / REVIEW 给出：具体命中的规则、原因、涉及对象，写入审计日志。目标指标：**拦截可解释率 100%**。透明的拦截本身是最好的营销素材。

### 2.4 策略即配置（Policy as Config）

让 DBA 自己写规则：表级（"audit_log 永远 BLOCK"）、模式级（"DELETE 必须 WHERE 带时间范围"）、阈值级（影响行数上限）。策略可见、可版本化、可导出。

> 现状备注：`TABLETALK_GATE_REVIEW_THRESHOLD` 目前是空转配置，正好借本项做实。

### 2.5 成本防护（管"贵"，不只管"坏"）

生产库被搞挂，一半不是恶意语句而是失控查询。执行前经 EXPLAIN 估算成本，超阈值进 REVIEW（"预计全表扫描约 X 行，确认？"）。安全故事从"不会写坏"升级为"既不会写坏，也不会写挂"。这是 DBA 每天真实的痛，竞品没有把它和写安全做成同一套闸门。

### 2.6 审计页延伸

现有审计页（异常优先 + 信号区）之上：写操作的周报摘要、异常模式提示（某人深夜批量 UPDATE）、每次出网调用的清单记录（与支柱三联动）。

## 3. 支柱二：方便（为不写 SQL 的人拆除两道墙）

畏惧有两层，都要拆：

### 3.1 拆恐惧层："物理上点不坏"

- 只读连接 + 三档闸门 + 审批兜底 = 新手的安全区。**onboarding 要把这个喊出来**："你可以放心乱点，因为物理上点不坏。"
- 星图 onboarding：连上陌生库，"先带你飞一圈你的数据宇宙"，节点点开有业务解释（知识库注释）。这是竞品给不了的哇哦时刻，也是产品的门面。

### 3.2 拆能力层："会问、信答案"

- **提问脚手架**：基于知识库领域标签生成"猜你想问"；空态给提问模板（按标签分组）。
- **追问链条**：每个答案下永远给 2–3 个可点的追问方向（"按周分组呢？"、"只看退款的呢？"），让不会提问的人顺着走。
- **SQL 退居幕后**：非技术视角下 SQL 默认折叠为"显示查询"小字；对话即产品，代码是可选展开项。
- **答案可追溯**：SQL 旁展示引用的表与知识库条目（像引用文献）。这是对 NL2SQL 准确率天花板的系统性缓解——错了让人看得出错在哪，而不是黑箱。
- **编辑器实时闸门检查**（开发者的"方便"）：schema 缓存 + 解析器在手，编辑时即做表/列名校验、未知列波浪线、无 WHERE 的 UPDATE 实时标红并预告将命中的规则。提笔纠错比提交弹窗体验高一个量级，且零模型调用。

### 3.3 常用问题库（复利资产的开端）

用户问过并确认过的好 SQL，一键存为团队共享的"业务问题/指标"（如"月度退款率"）。新人再问直接命中，不依赖模型当天的心情。知识库从"schema 语义层"长成"团队语义层"——用得越久越准、换工具舍不得迁走的护城河。

## 4. 支柱三：安全（"数据不出内网"的现实主义解法）

### 4.1 出网内容分层

一次 NL 查询会出网的内容分三层，分别对待：

| 层 | 内容 | 默认策略 |
|----|------|----------|
| 行数据 | 客户姓名、订单金额 | **永不出网**；聚合数据需过脱敏后才可 |
| 结构信息 | 表/列名、类型、注释 | 可出网；敏感表换代号（`t_17`） |
| 对话文本 | 用户问题本身 | 可出网；进入出网清单 |

### 4.2 四个机制（按投入从小到大）

1. **出网清单（Egress Manifest）**：每次模型调用前，UI 展示本次请求实际内容（"3 张表结构、知识库 2 条注释、6 轮历史，无行数据"），并记入审计。透明比纯洁更可信。
2. **本地脱敏网关**：AI gateway 出口加规则式脱敏层（正则 + 列类型识别 + 列级规则），确定性 tokenization（同值同假名，GROUP BY / COUNT DISTINCT 照常，回来能对上号）。做完这层，聚合数据的 `include_data` 可安全放开。**不是不让出网，是让出去的东西本身无害。**
3. **敏感度路由**：知识库标签体系加"敏感"一类（KB sensitive 机制已有雏形）。打标表：结构换代号、行数据一律不出、可强制路由本地模型。策略在 DBA 手里，用户无感。
4. **合同层兜底**：企业级 API 的零保留协议（ZDR / 不用于训练）关掉残余敞口。行业标准做法，写进方案大大方方讲。

### 4.3 三档模式（产品化的安全面）

| 档位 | 出网内容 | 模型 | 场景 |
|------|----------|------|------|
| 严格 | 纯结构（敏感表代号化） | 本地 / mock，可完全离线 | 高敏行业、演示 |
| 标准 | 结构 + 脱敏聚合 | 云端 | 企业日常默认 |
| 开放 | 逐查询授权的明文数据 | 云端 | 个人开发、低敏场景 |

管理员设默认档，用户可申请提档，一切进审计。mock 默认 + 全链路离线可跑的工程特性，在"严格档"里直接变成卖点与销售演示利器（30 秒离线展示完整体验，无需连库无需 key）。

## 5. 关键场景旅程（产品该长成的样子）

**场景 A · 业务新人第一次查数**：连接页 → 星图飞一圈（"这是你的数据宇宙"）→ 看到猜你想问 → 点一个 → 对话答案 + 折叠的 SQL + 追问链 → 采纳。全程零 SQL 书写、零恐惧。

**场景 B · DBA 给团队开门**：装好网关 → 配策略（表级 BLOCK、成本阈值、脱敏列规则）→ 设三档模式默认档 → 业务开始自助查数 → 审计页看到一切。DBA 的第一屏是控制台，业务的第一屏是提问框。

**场景 C · AI 要写数据了**：AI 生成 DML → 闸门 REVIEW → 爆炸半径卡片 + 星图点亮 + 回滚剧本 → 确认执行 / 转审批。新人发起、DBA 一键批（团队版）。

**场景 D · 出事了往回查**：审计页 → 定位语句 → 看到裁决路径（命中规则）、出网清单、关联会话 → 一键重放上下文。事故追溯是信任故事的售后证明。

## 6. 反目标（明确不做）

- **不做 BI**：图表、仪表盘、定时看板是深不见底的兔子洞，Metabase 免费且成熟；做了等于跳进最卷赛道、稀释主线。
- **不堆重型 RAG**：现有"关键词+向量+图谱"混合检索对表级路由够用；语义检索的时髦感不值得用隐私红线换。
- **不做跨库联邦查询**：工程深渊，与主线无关。
- **不做通用 chatbot**：对话只围绕"这个库里的数据"展开。

## 7. 路线图（按"验证什么假设"排序）

> 本节只保留"每阶段验证什么"的骨架；任务明细与验收标准以 `06-roadmap-and-acceptance.md` 为准，两处冲突时 06 优先。

### Phase 1 · 把信任做成 30 秒可演示的东西（近期）

- 编辑器实时闸门检查（复用 schema 缓存与解析器，零新依赖）
- 出网清单 + 审计联动（透明是信任第一步）
- 爆炸半径卡片（星图联动可后置）
- 星图 onboarding 放大 + "猜你想问"雏形
- 常用问题库最小闭环（保存/命中）
- **验证假设**：用户是否感知并认可"看得见的安全"，愿意因此选择我们。

### Phase 2 · 安全主张落地（中期）

- 本地脱敏网关（确定性 tokenization）
- 三档模式（策略面 + 审计报表）
- 成本防护（EXPLAIN 估算进闸门）
- 拦截可解释 100% + 策略即配置（做实 REVIEW_THRESHOLD 一族配置）
- **验证假设**：安全团队能否拿本产品过合规评审（这是进企业的门票）。

### Phase 3 · 从工具到网关（远期）

- 团队网关：连接凭证保险库（密码不再在聊天工具里传）、审批流、统一 AI 出口（用量与日志集中管控）
- 知识库团队化（注释/标签/问题库归团队所有）
- gate 独立开源（`tabletalk-gate` + 公开攻击测试集）作为分发飞轮
- 远期期权：透明代理（应用连它，过境 SQL 全过闸门全审计）——现在只需保证架构不堵死这条路
- **验证假设**：有没有团队愿意为"集中的可信 AI 数据入口"付费。

### 包装与分发（贯穿）

- M5 打磨以"离线 30 秒演示"为标准：不连库、不要 key、mock 全链路确定性。
- gate 开源带攻击测试集（100 条恶意 SQL 全拦截清单）——安全故事要可自己验证，不要"你说是就是"。

## 8. 北极星指标（防跑偏的锚）

> 指标定义以 `01-positioning-and-principles.md` §8 为准（两处为同一张表，修改时只改 01）。

| 支柱 | 指标 | 定义 | 目标 |
|------|------|------|------|
| 可信 | 拦截可解释率 | BLOCK/REVIEW 事件中附有具体规则与原因的比例 | 100% |
| 可信 | 成本拦截率 | 高成本查询在执行前被 REVIEW 的比例 | 可配置、有基线 |
| 方便 | 零编辑采纳率 | AI 答案未经修改 SQL 直接采纳的比例 | 核心健康度 |
| 方便 | 首答时长 | 新用户从连接到第一个满意答案的时间 | 分钟级 |
| 安全 | 出网可枚举率 | 有清单与审计记录的模型调用比例 | 100% |
| 复利 | 问题库命中率 | 经保存问题库直接命中的查询比例 | 持续上升 |

全部来自现有日志体系，工程上顺手，产品上是方向盘。

## 9. 设计原则（给未来一切功能决策的尺子）

1. **每个新功能先问**：它让信任更可信了吗？让查询更无惧了吗？两者皆无则不做。
2. **本地规则优先于模型判断**：凡涉及"守门"的决策（闸门、脱敏、路由）必须离线可跑、规则可读、结果可审计。模型只负责"写"，永远不负责"放行"。
3. **行数据默认不出网**；结构可以出去，出去的要留痕。
4. **透明优于纯洁**：宁可展示真实的限制（"这条查询需要明文数据，请提权"），不承诺做不到的纯洁。
5. **给 DBA 控制台，给业务提问框**：买家和用户是两个人，两个第一屏。
6. **确定性优先**：mock 默认、离线可演示、测试全绿——工程上的纪律就是商业上的弹药。

## 10. 风险与应对

| 风险 | 应对 |
|------|------|
| NL2SQL 准确率天花板，用户一次错答案即流失 | 答案可追溯（引用表/注释）；报告模式等结构化场景先出口碑；问题库沉淀降低对模型的依赖 |
| "安全"教育成本高，客户不信 | 攻击测试集公开可跑；出网清单可见；拦截可解释 100% |
| 个人版免费心智，团队版收费难 | 个人版完整可用（口碑），付费点放在"团队"（凭证、审批、集中管控、合规报表）——单人用不到的功能 |
| 开源 gate 被白嫖 | gate 开源是获客飞轮不是收入；收钱的在网关与团队功能 |
| 大厂/大模型厂商顺手做安全 | 我们的差异是"本地、模型无关、库级深耦合（FK 图谱/爆炸半径）"，通用护栏做不到这个深度 |
