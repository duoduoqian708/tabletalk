# 02 · 功能需求详规

> 每个功能条目统一格式：**目标 / 用户故事 / 功能逻辑 / 涉及现有模块 / 验收标准 / 阶段**。
> 阶段：P1=可信演示期 · P2=安全落地期 · P3=团队网关期（详见 06 路线图）。

## A 系列 · 可信（把引擎盖下的闸门推到台前）

### A1 拦截可解释（P1）

- **目标**：每次 BLOCK / REVIEW 都说清楚"为什么"，写进响应与审计。
- **用户故事**：作为 DBA，我看到 AI 的语句被拦，我要立刻知道命中了哪条规则、为什么，而不是一个干巴巴的"已拦截"。
- **功能逻辑**：
  - 闸门裁决结果（`app/safety`）扩展 `reasons: [{rule_id, message, objects}]` 字段，逐条列出命中的规则、规则文案、涉及对象（表/列/语句片段）。
  - 前端 REVIEW/BLOCK 弹层按列表渲染；审计 JSONL 每条记录带 `reasons`。
  - 规则文案中英双语（走现有 i18n 词典）。
- **涉及**：`app/safety/rules.py`、`api/query.py`、`audit/logger.py`、前端 SQL 卡 / 确认弹层。
- **验收**：审计中 100% 的 BLOCK/REVIEW 记录含非空 `reasons`；UI 上每条规则可读；pytest 增加断言覆盖每条规则的 reason 生成。

### A2 策略即配置（P2）

- **目标**：DBA 用配置写规则，闸门行为可组织级定制。
- **用户故事**：作为 DBA，我要规定"audit_log 表永远 BLOCK""DELETE 必须 WHERE 带时间范围"，并且知道它真的生效。
- **功能逻辑**：
  - 策略对象三类：**表级**（表名 -> ALLOW/REVIEW/BLOCK）、**模式级**（语句形态规则，如"DML 无时间谓词"、"TRUNCATE 一律 BLOCK"）、**阈值级**（影响行数上限）。
  - 落在 `RuntimeSettings`（现有 `data_dir/settings.json` 持久化 + `PUT /settings`），策略版本化（带 `version` 与 `updated_by`）。
  - 闸门规则引擎读取策略，优先级：表级 > 模式级 > 默认三档。命中策略的裁决在 `reasons`（A1）中标注"来自策略 vN"。
  - UI：设置抽屉新增"策略"页（DBA 控制台的一部分）。
- **涉及**：`app/core/settings.py`、`app/safety/`、settings API、前端 SettingsDrawer。
- **验收**：表级 BLOCK 策略使对该表的一切写操作 BLOCK 且 reason 标注策略来源；做实现处于空转的 `TABLETALK_GATE_REVIEW_THRESHOLD` 一族配置（当前它是持久化但无人读取的，见 CLAUDE.md「Verified realities」）；策略修改即时生效无需重启。

### A3 爆炸半径（P1 卡片 / P2 星图联动）

- **目标**：DML 确认前展示波及面，风险从"读"变成"看见"。
- **用户故事**：作为执行 DML 的人，我在点确认前要知道这条语句会波及哪些表、顺着 FK 影响到哪。
- **功能逻辑**：
  - REVIEW 预览接口（现有 `preview_rows` 同一通路）扩展返回 `blast`：
    - `direct`: 语句直接触及的表 + 预估影响行数（现有 COUNT 同 WHERE 逻辑）。
    - `cascade`: 沿 FK（知识库图谱的 FK 边）可达的表路径，标注"外键约束存在/不存在"，最多展开 2 层，防爆炸。
    - `constraints`: 命中的 FK/唯一约束名。
  - 确认弹层渲染"爆炸半径卡片"：表 chips + 路径图 + 行数。
  - **星图联动（P2）**：确认弹层出现时，星图上直接表琥珀色高亮、级联路径 FK 边闪红，用户点"在星图上看"或直接联动（交互细节见 03 §5）。
- **涉及**：`api/query.py` 预览分支、`knowledge/` 图谱数据、前端确认弹层、Graph3D。
- **验收**：demo 库对 orders 的 UPDATE 展示 order_items / payments 级联路径；无 FK 关联的表不出现在 cascade；卡片与星图高亮的表集合一致。

### A4 回滚剧本（P2）

- **目标**：DML 执行前自动附备份 / 回滚 SQL，"出事还能退回来"。
- **用户故事**：作为批准 DML 的人，我要在确认框里直接拿到回滚手段。
- **功能逻辑**：
  - UPDATE / DELETE：执行前生成"受影响行导出"SQL（`SELECT * ... WHERE <同谓词>`）或反向语句（INSERT 回放），附在确认弹层，一键复制 / 存为脚本文件。
  - 审计记录关联 `rollback_ref`（导出脚本的位置或语句哈希）。
  - 定位是**给手段，不承诺时光机**：UI 文案明确"回滚剧本仅供参考，执行前请核对"。
- **涉及**：`api/query.py`、`app/safety`（判定哪些语句需要剧本）、前端确认弹层、审计。
- **验收**：UPDATE/DELETE 的 REVIEW 弹层 100% 附带回滚剧本；INSERT 提供主键回放建议或明确说明无法自动回滚；剧本语句本身过闸门校验（防剧本自身越权）。

### A5 成本防护（P2）

- **目标**：闸门管"贵"不只管"坏"--失控查询和恶意语句杀伤力同级。
- **用户故事**：作为 DBA，我不怕人写坏数据，怕一张亿行表的全表扫描把库拖挂。
- **功能逻辑**：
  - `DialectAdapter` 新增 `explain()`：PG / MySQL 用原生 `EXPLAIN` 解析估算行数；SQLite 的 `EXPLAIN QUERY PLAN` **没有行数字段**，用 SCAN / SEARCH 判别 + schema 已有的 `row_count` 估算（SCAN 时上界 = 表行数，SEARCH 时按索引选择性粗估）。
  - 超过阈值（策略 A2 的阈值级配置，默认 10 万行估算）-> 裁决升为 REVIEW，reason 标注"预计扫描 ~N 行"。**只读查询同样适用**（这是与写防护的关键差异）。
  - EXPLAIN 失败的方言：降级为不做成本检查，绝不因检查失败阻塞查询（可用性优先），但审计记录降级原因。
- **涉及**：`app/core/dialects/*`（新增 explain）、`app/safety/`、`api/query.py`。
- **验收**：SQLite demo 上产生全表 SCAN 的语句（按 row_count 估算超阈值）进 REVIEW，索引等值查询（SEARCH）不升档；PG/MySQL 按估算行数判定；EXPLAIN 异常不影响执行；审计含成本估算字段。

## B 系列 · 安全（受控出网）

### B1 出网清单 Egress Manifest（P1）

- **目标**：每次模型调用，用户看得见发了什么，审计记得住发了什么。
- **用户故事**：作为安全负责人，我不需要相信你们"没发敏感数据"--我要亲眼看到每次请求的内容清单。
- **功能逻辑**：
  - AI 请求管道（`app/ai/context.py` 构建完成后、gateway 发送前）生成清单对象：
    ```
    { tables: [..], kb_docs: N, history_turns: N, include_data: bool,
      redactions: [...], mode: strict|standard|open, ts, model }
    ```
  - UI：AI 轨发送前折叠展示"本次将发送：3 张表结构 · 2 条知识库注释 · 6 轮历史 · 无行数据"；流式回复中保持可展开。
  - 审计：JSONL 新增 `egress` 事件类型（或在聊天事件上附清单）。
- **涉及**：`app/ai/context.py`、`gateway.py`、`loop.py`（SSE 增 `manifest` 事件）、`audit/logger.py`、前端 AiRail。
- **验收**：所有模型调用（chat / selection / intent / report / test）均有清单；清单内容与实际 payload 一致（pytest 对 payload 序列化做断言）；出网可枚举率 100%。

### B2 本地脱敏网关（P2）

- **目标**：出网内容本身无害化--不是不让出网，是让出去的东西没有毒。
- **用户故事**：作为安全负责人，我要允许业务用聚合数据让 AI 写报告，但客户手机号永远不能出现在任何请求里。
- **功能逻辑**：
  - 位置：`ai/gateway` 出口的规则式脱敏层（正则 + 类型推断 + 列规则），**规则式而非模型式**（原则 2）。
  - 三种规则：
    1. 模式匹配：邮箱 / 手机号 / 身份证 / 银行卡 / IP（内置正则库）。
    2. 列类型推断：列名语义（phone/email/id_card/name/address）+ 列类型。
    3. 列级显式规则：DBA 在知识库表注释或策略里标"此列敏感，一律 token 化"。
  - **确定性 tokenization**：`token = 短哈希(HMAC(值, 本地盐))` 映射为 `[EMAIL_1]` `[PHONE_2]` 形式；同值永远同 token -> 模型可 GROUP BY / COUNT DISTINCT，结果可对回原值；盐存本地 `data_dir`，永不出网。
  - 作用范围：`include_data=true` 放开的前置条件（标准档下聚合行数据必须先过此层）；对话文本同样过（用户问题里贴的敏感串也被打码）。
  - 逆向映射仅在本地结果展示层使用，发往模型的方向永远是 token。
- **涉及**：新增 `app/safety/redact.py`（与闸门同目录，同"本地可信层"哲学）、`ai/tools.py`（run_query 返回数据的出口）、`ai/gateway.py`。
- **验收**：单测覆盖每类正则与列规则；同一手机号在不同请求中 token 一致；含敏感列的行数据出网后经扫描器（测试内置）零命中原始值；性能：千行聚合脱敏 < 50ms。**前提**：demo 库 seed 需先补充含敏感数据的列（手机号 / 邮箱样式），否则验收无米下锅。

### B3 敏感度路由（P2）

- **目标**：敏感表的结构都不明文出网。
- **功能逻辑**：
  - 知识库标签体系（现有领域标签 draft->确认流程）新增"敏感"标签，走同一套人工确认工作流。
  - 打标表进入模型上下文时**代号化**：`customers` -> `t_17`，列名 -> `c_3`，注释剥离；回答回来按映射还原展示给用户。
  - 可选强制路由：敏感表相关查询路由到本地模型 / mock（模型配置见现有 gateway 三 provider）。
- **涉及**：`knowledge/`（标签类型扩展）、`ai/context.py`（代号化 + 还原）、intent 路由。
- **验收**：敏感表查询的出网清单（B1）中无明文表名/列名；用户看到的回复中表名已还原；非敏感查询行为不变。
- **修订（2026-08-23，08 §8.2）**：补**往返不变式**与**执行前还原**（均为【目标】，现状未实现）：① 模型产出的 SQL 在过闸门与执行前先 `decodify_text` 还原（现状 tool args 原样执行，敏感表 AI 查询报 `no such table: t_17`，核心路径断裂--审计 2026-08-21 B3#3）；② tool result 回喂模型前表/列名代号化，模型可见世界恒代号；③ 审计记录真实表名并注明与清单代号的对应。新增验收：敏感表 AI 查询端到端可执行；回喂模型的 tool result 中无真实敏感表/列名。

### B4 三档模式（P2）

- **目标**：安全从"道歉式宣传"变成有 UI、有策略、有日志的功能面。
- **功能逻辑**：

  | 档位 | 出网内容 | 模型 | 场景 |
  |------|----------|------|------|
  | 严格 | 纯结构（敏感表代号化） | 本地 / mock，可完全离线 | 高敏行业、演示 |
  | 标准 | 结构 + 脱敏聚合 | 云端 | 企业日常默认 |
  | 开放 | 逐查询授权明文 | 云端 | 个人、低敏 |

  - 配置：`RuntimeSettings` 增加 `privacy_mode`；管理员设默认档；用户申请提权（开放档逐查询弹授权确认，写审计）。
  - 严格档的一键体验：设置页"离线模式"开关 = 严格 + mock provider + 禁用云端测试按钮--销售演示用。
- **涉及**：`settings.py`、`ai/`、前端设置抽屉 + 授权弹层、审计。
- **验收**：三档行为符合表格；档位切换即时生效并审计；严格档下抓包测试确认 payload 无任何行数据与敏感结构。

## C 系列 · 方便（拆除两道墙）

### C1 编辑器实时闸门检查（P1，体验跃迁优先级最高）

- **目标**：从"提交后拦截"到"提笔就纠错"。
- **用户故事**：作为写 SQL 的开发者，我拼错列名要在没执行时就看到波浪线，写无 WHERE 的 UPDATE 时编辑器直接标红告诉我闸门会拦。
- **功能逻辑**：
  - 客户端 lint（零模型调用）：利用 schema 缓存 + 前端引入 sqlglot 的 wasm 或后端 `/sql/lint` 轻端点（选型见 05 §4）。
  - 规则集 v1：
    1. 表名/列名实时代码高亮（存在的绿色下划线装饰，悬停弹列卡片）。
    2. 未知表/未知列 -> 红色波浪线 + "closest suggestion"（编辑距离）。
    3. 语句形态预判：无 WHERE 的 UPDATE/DELETE、缺少 LIMIT 的大表 SELECT -> 行内警告图标，悬停显示"执行时将触发 REVIEW（规则：xxx）"。
    4. 多语句混合读写 -> 提示将 BLOCK。
  - lint 结果与闸门规则**同一来源**（规则 ID 共享），保证编辑器说的和执行时发生的一致--这是本功能的灵魂，绝不另造一套规则。
- **涉及**：schema API（已有 30s 缓存）、sqlglot、前端编辑器组件。
- **验收**：拼错列名实时波浪线且建议正确；无 WHERE UPDATE 显示与 A1 一致的规则文案；关闭网络（mock）时 lint 仍全量工作；lint 延迟 < 100ms（千行编辑器输入不卡）。

### C2 猜你想问 + 提问模板（P1）

- **目标**：拆"不会问"之墙。
- **功能逻辑**：空态与对话起始，基于知识库**已确认**领域标签生成 3-5 个建议问题（规则模板："按{时间}统计{标签相关表}的{数值列}…"，本地拼装，不调模型）；点击即填入提问框。语言跟随现有 i18n。
- **验收**：demo 库空态出现可点的问题且全部可执行出结果；问题引用的表均属已确认标签；不发起任何模型调用。

### C3 追问链条（P1）

- **目标**：让不会提问的人顺着走。
- **功能逻辑**：每个答案卡片下生成 2-3 个可点追问（"按周分组？""只看退款的？""加个同比？"）；生成优先走规则（改写上一个意图的维度/过滤），无规则可用时随请求让模型附带返回（进 prompt 约定，不额外调用）；点击 = 以该问题续问。
- **涉及**：`ai/loop.py`（SSE 事件扩展）、intent 层、前端答案卡。
- **验收**：每轮答案有追问；点击追问不重复建会话；追问改写命中上一查询的表集合（上下文连续性）。

### C4 SQL 折叠 / 双视角（P1）

- **功能逻辑**：对话中的 SQL 卡默认折叠为"显示查询"小字行；展开记忆存用户设置（`ui_pref`）；设置里有"始终显示 SQL"开关（开发者视角）。
- **验收**：新用户默认折叠；开关全局生效；折叠态不丢失"复制 / 去编辑器执行"入口。

### C5 答案可追溯（P1）

- **目标**：对 NL2SQL 准确率天花板的系统性缓解--错了让人看得出错在哪。
- **功能逻辑**：SQL 卡旁展示引用 chips：本查询用了哪些表（点击跳星图定位 D1）、参考了哪些知识库条目（点击展开原文）；模型回复的叙述句凡来自聚合数字的，标注来源行（报告模式已有 include_data 基础）。
- **涉及**：`ai/loop.py`（工具调用记录已存在，透传到 SSE）、前端 SQL 卡、知识库文档组件。
- **验收**：每张 SQL 卡可见表引用且与 SQL 中实际表一致；KB 引用可点开原文；无引用时不显示空区块。

### C6 常用问题库（P1 最小闭环 / P3 团队化）

- **目标**：复利资产--用得越久越准，换工具舍不得走。
- **功能逻辑**：
  - 保存：任意一轮"问题 + 确认过的 SQL"一键存为命名条目（"月度退款率"）；可设参数占位符（`{month}`）。
  - 命中：新提问先走本地问题库匹配（问题文本相似 + 表集合匹配），命中直接执行免模型调用；未命中走正常链路。
  - 组织：个人库起步（P1，存 `data_dir`）；P3 随知识库团队化归团队所有，带可见性权限。
- **涉及**：新 `app/core/questions.py` + API、前端保存/管理 UI、chat 入口前置匹配。
- **验收**：保存-再问-命中-执行零模型调用（mock 下可验证）；问题库命中率进北极星指标埋点（06）。
- **修订（2026-08-23，08 §7）**：① 匹配在**脱敏前的原文**上进行（现状在脱敏之后，含敏感串的问题永不命中）；② 命中后不再静默执行，改为**命中确认卡**（展示"问题库命中 + 将执行的 SQL"，用户点执行才跑）；③ 保存时校验只收只读问题（DML 问题不可保存，命中执行留待后续）；④ 匹配阈值可配，并补误命中反例用例（相似但不该命中的问题对）。

## D 系列 · 星图增强（P1，均基于现有 Graph3D）

### D1 搜索定位（P1）

- **功能逻辑**：星图工具栏搜索框，输入表名（前缀/模糊），回车或点结果 -> 视图飞向该节点（缓动 yaw/pitch/zoom 至节点居中）并临时点亮；持续输入实时过滤下拉。
- **验收**：14 表 demo 全部可定位；飞行动画 < 1.2s 且期间交互可打断；无结果时提示而非空转。

### D2 显式旋转控制（P1）

- **功能逻辑**：星图角落提供"暂停/恢复自转"切换（当前为点击隐式停止，多数人不知道）；状态持久到会话内。保留现有隐式行为：交互即停、静止 1.2s 后缓升恢复（详见 03 §5 交互规范）。
- **验收**：按钮状态与实际自转一致；暂停时静置不自转、恢复后缓动启动。

### D3 选中后邻居局部散开（P1）

- **功能逻辑**：节点选中弹信息卡时，其直接邻居短暂向外散开 20-30% 距离（1s 缓动），降低遮挡；取消选中回位。实现于布局层（对邻居位置乘径向系数），不动 FK 数据。
- **验收**：散开期间连线跟随、可点击；连续切换选中不抖动（动画可打断）。

### D4 Onboarding 飞行（P1）

- **功能逻辑**：首次进入工作台，星图执行一段 ~4s 的引导飞行（自转一周 + 缓慢拉近），配文案"这是你的数据宇宙--点击任意节点查看"；任意交互立即打断并永不再次出现（本地记忆）。
- **验收**：仅首次出现；打断即时；文案走 i18n。

## E 系列 · 团队网关（P3）

### E1 连接凭证保险库

- **功能逻辑**：网关集中持有连接凭证（服务端加密存储，密钥来自部署时注入的主密钥）；成员前端只见连接名与元数据，永不下发密码；连接 CRUD 权限按角色（admin / member）。
- **验收**：浏览器 DevTools 全程抓不到任何连接密码；成员角色无法导出凭证（无此 API）。

### E2 DML 审批流

- **功能逻辑**：REVIEW 语句可标记"转审批"进队列；DBA 视图一键批准 / 驳回（附批注）；批准后在原上下文执行，全程审计关联（申请会话、批准人、时间）。策略可配"哪些表 / 哪些角色必须走审批"。
- **验收**：未批准语句无法执行；驳回后申请人收到通知；审计可完整还原审批链。

### E3 统一 AI 出口

- **功能逻辑**：组织级模型配置（一个云端点 + 备用本地模型），成员不可自配云端 key；用量按成员统计（token 数、请求数）；出网清单与三档模式在网关层统一执行。
- **验收**：成员设置页无 key 输入项；用量报表与清单记录一致。

### E4 账号与鉴权演进

- **功能逻辑**：从单用户共享 token（现状：`data_dir/tabletalk.token` + `/bootstrap` 免鉴权发放）演进为 OIDC / 本地账号体系；审计与权限全部 per-user；`/bootstrap` 仅在单机模式保留。**注意**：现状 CORS 全开 + LAN 可达 bootstrap，多用户化时必须一并收紧（见 05 §5 安全债）。
- **验收**：单人模式零配置不变；团队模式浏览器无需接触任何 token；未认证请求 401。

## G 系列 · AI 规划与执行（08 的需求面，2026-08-23 立项）

> 设计依据：08 v0.2 与评审纪要 `docs/pending-decisions/2026-08-22-ai-planning-execution.md`（D1~D15）。实施顺序与任务分解见纪要第六/七节。

### G1 意图分层与 Preflight 统一（P1）

- **目标**：一次判定出"要不要动库、动哪个面、查什么领域"，且首包不被前置调用拖垮。
- **用户故事**：作为用户，我问"你好"不被拉着跑一遍向量检索；问"有哪些表"直接得到结构答案；任何问题 1.2 秒内看到第一反应。
- **功能逻辑**：
  - 意图两平面（封闭集、版本化）：数据面 `query/report/schema/write/ddl` + 控制面（分批）+ `offtopic` 兜底；单标签，**拿不准当 query**；写意图判定保守。
  - preflight 统一 owner：关键词快判 ->（拿不准）**一次** LLM 返回 `{intent, tags}`；全程 ≤2s，超时/异常降关键词；脱敏/manifest/egress 审计各恰一次（取代现状三次独立调用及其内联重复）。
  - 判定输入含对话尾部（解决澄清阶段裸回答的判类）；追问轮 L2 种子并入上轮表集合。
  - 预测意图 vs 实际路径不一致率入审计。
- **涉及**：新 `ai/preflight.py`，收敛 `intent.py`/`agent/dispatcher.py`/`loop.py`。
- **验收**：六类意图各≥2 例句的单测；超时降级路径；egress 审计恰一条；`intent.py` 无内联审计代码；"你好"零 KB 组装零检索。

### G2 会话记忆与结果工件（P1）

- **目标**：会话成为有记忆的执行单元，"前面那个结果"可寻址可复用。
- **用户故事**：作为用户，我问"导出前面那个结果"、"把刚才的按周再来一遍"，AI 知道我说的是什么。
- **功能逻辑**：
  - 记忆随 session 走、服务端落库；历史组装由服务端负责（`req.messages` 降级为兼容通道）；**切库自动换 session**（连接边界=会话边界）。
  - 每张 sql_card 落 `result_id`（与 report `[r id]` 统一为一套）；引用解析由模型在历史中完成；新增 `load_result` 工具按 id 取工件，**恒过脱敏管道 + 行数上限**。
  - 上下文压缩 v1（只压缩不截断）：机械优先、卡片骨架（id/表名/verdict/rowcount）不可压缩、LLM 摘要走单管道+审计、当前轮与未决确认豁免。
  - 追问三路径：改写重查（过闸门）/ 工件操作（不查库）/ 数据回加工（引导写新 SQL，工件只看形状）。
- **涉及**：`loop.py`、`state.chats`、`dto.py`、新 `load_result` tool、新 `ai/compress.py`、前端会话切换。
- **验收**：同 session 连续两问，第二问上下文来自服务端；"前面第 2 个结果"命中正确 id；standard 档工件回喂被 redact、strict 拦行数据；压缩后骨架仍含全部 result_id；LLM 摘要调用有 egress 审计；切库后追问不带旧库上下文。

### G3 DML 确认协议（P1）

- **目标**：chat 内写操作从"模型说了算"变成"人确认才算"，且确认的与执行的是同一条语句。
- **用户故事**：作为执行 DML 的人，我看到的预览、我点的确认、真正执行的 SQL、事后审计里那条记录，四者是同一件事。
- **功能逻辑**：三段协议（见 08 §6）：REVIEW 处终止 loop -> 确认卡带 `confirm_token`（绑 SQL 哈希、一次性、10 分钟过期）-> 确认执行时**重新过闸门** + 审计带 token/turn_id 与 preview 闭环；取消/拒绝写回历史；审批流（E2）同协议，顺修"批准执行绕过闸门"。
- **涉及**：`ai/tools/sql.py`、`loop.py`、`api/query.py`、`api/approvals.py`、session 存储、前端确认卡。
- **验收**：TOCTOU 用例（确认时换 SQL 被拒）；过期重走 preview；run_dml 后模型无后续轮次；确认执行审计能关联 preview；批准的无 WHERE UPDATE 仍被闸门拦。

### G4 引导式拒答（P1）

- **目标**：平台外话题体面地拒答并引导回平台能力，不做通用闲聊。
- **功能逻辑**：offtopic -> refusal 技能：无工具，prompt 限定"只拒绝+引导"（注入连接名/已确认标签做具体引导）；每次调用有 manifest+egress；strict 降级本地固定文案。
- **涉及**：`skills/builtin/`、`preflight.py`。
- **验收**："天气"得到拒答+具体引导；strict 下离线拒答；拒答调用 100% 有清单审计。

### G5 检索封顶、纠错与覆盖率（P1）

- **目标**：候选子图可控、检索错了能自愈、参数调优有数据。
- **功能逻辑**：融合候选封顶 20（标签 > 向量 > 2 跳外围的砍表顺序）；`run_query` 报 no such table/column 时注入一次完整表清单（有界纠错，计入 MAX_TURNS）；done 时候选覆盖率入 `context_meta`+审计。
- **涉及**：`context.py`、`knowledge/store.py`、`tools/sql.py`、`loop.py`。
- **验收**：大候选集封顶与优先级单测；错表 SQL 一次重写成功用例；审计含 coverage 字段。

### G6 平台工具注册制与审计问答（P2，批次 1）

- **目标**：平台功能以注册 tool 的方式对 AI 开放，"指定的能力"而非"全部能力"。
- **用户故事**：作为用户，我问"我刚才改了什么"、"今天哪些语句被拦了"，AI 直接给我审计回顾。
- **功能逻辑**：工具注册规格五件套（name/schema/trust/confirm/audit）+ admin 可开关；**密钥直入 vault**（连接串本地解析，模型只见结构参数）；批次 1 仅 `query_audit` + `get_last_operations` + `audit_qa` 技能；系统操作审计 `source=system_tool`；永不注册清单（DDL 执行、数据源删除、模型配置修改、任意代码执行）写死在 08 §4.3。
- **涉及**：`tools/registry.py`、新平台 tools、`skills/builtin/`、`audit/logger.py`。
- **验收**：无 trust 元数据的工具拒绝注册；"我刚才干了什么"返回正确回顾且回喂过脱敏；每次平台工具调用有 `source=system_tool` 审计。

### G7 技能开关（P2）

- **目标**：用户决定自己的 AI 有哪些能力；权限不被勾选穿透。
- **功能逻辑**：设置页技能列表勾选（三层权限：工具层信任不可开关/技能层能力用户勾选/意图层路由）；地板 `query`+`refusal` 常开；关闭技能给降级文案（不产生死胡同）；团队模式组织策略 ∩ 个人勾选（最严者胜）；勾选变更写审计。
- **涉及**：`api/settings.py`、`skills/registry.py`、前端设置页。
- **验收**：地板不可关；关闭 write 后"删掉测试订单"得到"此能力已关闭"引导而非错误；成员勾选不能恢复管理员禁用项；勾选产生审计事件。
