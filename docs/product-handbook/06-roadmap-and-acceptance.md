# 06 · 路线图与验收

> 每个 Phase 的结构：**目标 -> 任务表（含验收标准）-> 验证假设 -> 退出条件**。
> 排期不写死日期，按"假设验证"推进：上一阶段的退出条件未达成，不盲目开下一阶段。

## Phase 0 · 收尾与开源准备（当前）

**目标**：把已完成的 M2-M4 产品打磨到"陌生人能 30 秒跑起来"。

| 任务 | 验收标准 |
|------|----------|
| M5 打包/打磨（既有里程碑） | `python3 backend/tabletalk.py` 幂等秒起；README 双语；演示库自动播种 |
| 星图增强 D1-D4 | 按 02-D 验收条目逐项通过（含 Playwright 回归，见 §4 测试规范） |
| e2e 体系固化 | 现有像素断言脚本（星图交互回归）纳入 `frontend/scripts/` 正式维护，CI 可跑 |
| License 与仓库整理 | Apache-2.0；贡献指南；攻击测试集占位（F2 骨架） |

## Phase 1 · 把信任做成 30 秒可演示的东西

**验证假设**：用户能否感知并认可"看得见的安全"，并因此选择我们？

| 任务 | 验收标准（可测） |
|------|------|
| A1 拦截可解释 | 审计 100% BLOCK/REVIEW 含非空 reasons；每条规则有双语文案与单测 |
| B1 出网清单 | 全部模型调用有清单且 payload 一致性有测试；SSE manifest 事件；出网可枚举率 100% |
| A3 爆炸半径卡片 | demo 库 UPDATE orders 展示 FK 级联路径；无关联表不出现 |
| C1 编辑器实时闸门检查 | 未知列波浪线 + 建议；编辑器规则文案与 A1 同源；离线可用；lint < 100ms |
| C2 猜你想问 | 空态 3-5 个可执行建议问题，零模型调用 |
| C3 追问链 | 每答案 2-3 追问；点击续问不重建会话 |
| C4 SQL 折叠 | 默认折叠 + 设置开关 + 记忆 |
| C5 答案可追溯 | SQL 卡表引用 chips 与实际一致；KB 引用可点开 |
| C6 问题库最小闭环 | 保存->再问->零模型调用命中执行；命中率埋点 |
| F2 gate 拆库 + 攻击集 | 独立包可安装；≥100 条攻击 SQL 全拦截、CI 徽章 |

**退出条件**：开源发布后获得首批真实用户反馈（issue/讨论 ≥ 20 个独立用户参与），且"看得见的安全"在反馈中被自发提及（定性信号）。

## Phase 2 · 安全主张落地（过合规评审）

**验证假设**：安全团队能否拿本产品通过内部评审（进企业的门票）？

| 任务 | 验收标准 |
|------|------|
| B2 脱敏网关 | 三类规则全覆盖单测；同值同 token；出网扫描零命中原始敏感值；千行 < 50ms |
| B4 三档模式 | 三档行为符合规格；提权逐查询授权 + 审计；严格档一键离线 |
| B3 敏感度路由 | 敏感表代号化出网；回复还原展示；KB 敏感标签走确认流 |
| A2 策略即配置 | 表级/模式级/阈值三类规则生效并即时热更新；REVIEW_THRESHOLD 做实 |
| A4 回滚剧本 | UPDATE/DELETE 100% 附剧本；剧本自身过闸 |
| A5 成本防护 | SQLite 全表 SCAN（按 row_count 估算）进 REVIEW、PG/MySQL 按估算行数进 REVIEW；SEARCH/索引查询不升档；EXPLAIN 失败放行并审计降级 |
| 审计延伸 | 出网记录、周报摘要、异常模式提示 |

**退出条件**：≥ 3 家真实企业用"标准档 + 脱敏"跑生产或准生产环境，其中 ≥ 1 家通过内部安全评审（访谈验证）。

## Phase 3 · 从工具到网关（商业化验证）

**验证假设**：有没有团队愿意为"集中的可信 AI 数据入口"付费？

| 任务 | 验收标准 |
|------|------|
| E4 账号鉴权 | OIDC/内置账号；单机模式零配置不变；CORS/bootstrap 债务清偿 |
| E1 凭证保险库 | 前端全程抓不到密码；角色化连接管理；明文迁移工具 |
| E2 DML 审批流 | 未批不执行；审计还原完整审批链 |
| E3 统一 AI 出口 | 组织级模型配置；成员用量统计与清单一致 |
| C6 问题库团队化 | 团队可见性权限；迁移个人库 |
| proxy 期权 | 仅保持架构不堵死（05 §3.4），**不立项** |

**退出条件**：≥ 5 个付费团队（或等价的强购买意向合同）。

## 北极星指标埋点清单（P1 起逐步落）

| 指标 | 数据源 | 埋点字段 |
|------|--------|----------|
| 拦截可解释率 | 审计 | 裁决事件 `reasons` 非空率 |
| 成本拦截率 | 审计 | 成本升档事件 / 高成本语句总数 |
| 零编辑采纳率 | chat.db + 审计 | 答案采纳时 SQL 是否被修改（编辑器 diff 标志位） |
| 首答时长 | chat.db | 建连接 -> 首个采纳答案的时间差 |
| 出网可枚举率 | 审计 | egress 事件 / 实际模型调用总数（gateway 侧双记） |
| 问题库命中率 | chat 入口 | 命中标记 + 来源问题库条目 id |

统计本地聚合（审计文件扫描脚本即可，`npm run` / `python -m` 一键报表），**不做云端遥测**（与隐私主张自洽--自己都不出网，才好意思要求模型出网受控）。

## 测试规范（延续现有纪律）

- 后端：pytest 全绿是合并前提；新功能必须带测试（安全类逻辑带攻击用例）。
- 集成：PG/MySQL docker 门控保持。
- 前端：typecheck + build 门控；关键交互路径 Playwright e2e（星图回归用像素断言法：饱和色聚类找节点 + 帧间位移测自转 + teal 中点验证邻居正确性，脚本存 `frontend/scripts/`，**验证脚本禁止依赖人工看截图**）。
- 攻击测试集：gate 包 CI 独立跑，任何一条由拦截转放行即 CI 失败。
