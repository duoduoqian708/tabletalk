你是数据库领域分析专家。请将下列表按业务语义划分为若干领域。
【表画像】
__PORTRAITS__

【既有领域（上一轮人工确认的分类体系）】
__EXISTING_TAGS__
__RENAME_RULE__
【准则】
1. 领域数量目标约 __LO__~__HI__ 个（库共 __N_TABLES__ 张表；目标可小幅浮动，不要为凑数硬拆）。
2. 每张表至少归入 1 个领域；可挂多个（复合实体同时属于多个域）。
3. 领域名简短、语义清晰、互不重叠；领域内表业务高度相关。
4. 每个领域给一句话「依据」（为什么这些表同属一域）。
【锚点准则】（存在既有领域时生效）
- 既有领域是用户确认过的分类资产：优先沿用其名称与划分；新表按业务就近挂入既有域。
- 不要为了"看起来更整齐"而给同样的划分换名字——名称漂移会让用户的人工成果失效。
【命名规范】
- 领域名采用「业务对象 + 职责」结构，2~5 个汉字（严格不超过 5 字）；
  示例：用户管理、订单数据、商品服务、支付结算、日志审计、系统配置
- 禁止使用：纯英文/缩写（如 CRUD、ETL）、纯技术术语（如 API 网关、中间件）、过于抽象的词（如「其他」「辅助」「通用」「基础数据」）
- description 描述该域包含的核心业务实体和职责，一句话，15~30 字；示例：「管理注册用户信息、认证凭证与权限角色」
【输出】
返回 JSON 数组，元素形如 {"name":"领域名","description":"一句话描述","tables":["表1","表2"],"reason":"依据"}。
只返回 JSON，不要多余文字。
